# Excel での検証（xlsx の読み書き・数式の計算・表示形式）

xljs の xlsx の扱いは、それまで LibreOffice との突き合わせでしか確かめていなかった。LibreOffice は Excel が開けないファイルも開き
（`_xlfn.` の付いていない新しい関数、`G1#` のままのスピル参照など）、表示形式の解釈も Excel と違うので、互換の確認には使えない。
2026-11-15 に Windows 実機の Excel（Office Professional Plus 2021、16.0.20326）を COM から動かして確かめた。

## 1. 道具（`tools/excel-verify/`）

```
cargo build
pwsh -File tools/excel-verify/run.ps1      # 各項目の PASS / FAIL。差の詳細は %TEMP%\xljs-excel-verify\*.txt
```

| ファイル | 役割 |
|---|---|
| `run.ps1` | 全項目を流す。失敗があれば終了コード 1 |
| `dump.js` | xljs でブックの全セル（値・数式・表示）を JSON に出す。`calc` で `book.calculate()` してから、保存先を渡せば保存も |
| `excel-dump.ps1` | Excel で同じ形の JSON を出す。`-Recalc`（CalculateFull）、`-Manual`（手動計算で開き、ファイルの保存値を読む）、`-Wide`（列幅を広げてから表示を読む） |
| `compare.py` | 2 つの JSON を比べる（値は相対誤差 1e-15） |
| `excel-make.ps1` | Excel 自身にブックを作らせる（標準の表示の数値、表示形式、Excel で入力した数式・テーブル・書式） |
| `make_builtin.py` | 組み込みの表示形式 0〜81 を定義なしで参照するブック（Excel が保存するのと同じ形） |
| `write.js` | xljs でいろいろ書いたブック |
| `open-test.ps1` | Excel で開けるかだけを見る（開けないファイルは修復のダイアログを出さずに失敗する） |

Excel の COM から読む `Text` は列幅で変わる（`####`、桁の切り詰め）。表示を比べるときは `-Wide` を付ける。
このマシンの Excel は 2021 なので、Microsoft 365 にしかない関数（`LAMBDA`・`TAKE`・`TEXTSPLIT` など）は Excel 側が `#NAME?` になる。

## 2. 確かめられたこと

- **数式の計算**: `testdata/xlsx/calc.xlsx` の全数式（139 個の関数の例、配列数式・スピル・テーブル・共有数式・名前）の値が、Excel の再計算と相対誤差 1e-15 で一致する。
  違うのは「保存値」シートの、Excel にも計算できない数式（マクロ関数・外部参照・未定義の名前）だけ（xljs は保存値を残す設計）。
- **計算して保存した値**: xljs が `calculate()` して保存したブックを Excel が再計算せずに読むと、全セルの値が xljs の結果と同じ。
- **Excel が作ったブックの読み込み**: 値と数式はすべて同じ（下の差を除く）。
- **書き込み**: 値・数式（`_xlfn.`・`_xlpm.`・`ANCHORARRAY`・動的配列のメタデータ）・結合・フォント・塗り・配置・罫線・表示形式・列幅・行の高さ・ウィンドウ枠の固定・フィルター・既定フォント（游ゴシック）が Excel で意図どおりに見える（下の制御文字の件を除く）。
- **往復**: `testdata/xlsx`・`testdata/book`・`examples/data` のブックと Excel が作ったブックを開いて保存しても、値・数式・表示・表示形式は変わらない（下の 3 つを除く）。

## 3. 見つかった差（未対応）

### 3.1 Excel で開けなくなる・内容が変わる（優先して直す）

| 起きること | 原因 | 場所 |
|---|---|---|
| U+0001 などの制御文字を含む文字列を書くと、**ブック全体が Excel で開けない** | 制御文字を XML にそのまま書いている。Excel は `_x0001_` と書く。逆に文字列 `_x000D_` はそのまま書かれ、Excel では CR になる（`_x005F_x000D_` と書くべき）。読むときも `_x0001_` を元の文字に戻していない | umya（共有文字列・インライン文字列の読み書き） |
| 図形を含むブックを開いて保存すると、**Excel で開けない／図形が消える** | `<a:ln w="0"/>` のような空の `a:ln` を開始タグとして読み、次の `</a:ln>` まで読み進める。後ろの図形が前の図形に飲み込まれて消え（`shapes.xlsx` のワードアート 18）、`a:ln` に `solidFill` と `noFill` が両方入って Excel が開けなくなる | umya `Outline::set_attributes` の呼び出し 3 か所（`run_properties.rs`・`spreadsheet/shape_properties.rs`・`charts/shape_properties.rs`）が空要素と開始タグを区別していない |
| 画像を含むブック（`print.xlsx`・`shapes.xlsx`）を保存すると Excel で開けない | 画像の `<a:prstGeom prst="rect">` が `prst=""` で書かれる（`a:` の名前空間を要素ごとに宣言しているファイルで起きる） | umya（画像の `spPr`） |
| ワードアートの文字の変形（アーチ・円など）が保存で消える | `a:bodyPr` の `a:prstTxWarp` を書き戻していない | umya |
| 定義のない組み込みの表示形式（ID 5〜8・23〜26・41〜44・63〜81）が、保存すると **別の表示形式に変わる** | umya が知らない ID は表示形式の文字列が空になり、スタイルの重複除去で同じものとみなされて 1 つ（ID 5）にまとめられる。Excel は ID 5〜8・41〜44 を定義付きで保存することが多いので、Excel のブックで起きることは少ない | umya（スタイルの重複除去） |

### 3.2 表示（`cell.text`・`toObjects({ text: true })`・PDF の印刷）

`src/api/numfmt.rs` と `src/api/xlsx.rs` の `builtin_code`。業務のブックでよく使うものから。

- **端数の丸め**: Excel は 0.5 を 0 から遠いほうへ丸める（`#,##0` で 1234.5 → `1,235`、`0` で 0.5 → `1`）。xljs は最近接偶数で `1,234`・`0`。
- **経過時間 `[h]:mm`・`[h]:mm:ss`**: 未対応（`[h]:mm` は `[h]:mm2`、組み込み ID 46 は 24 時間で折り返す）。勤怠のブックでよく使う。
- **曜日 `aaa`・`aaaa`**: 未対応（`aaaa46113`）。Excel は `水`・`水曜日`。
- **組み込みの表示形式の表**（日本語版 Excel が表示するもの。`tools/excel-verify/make_builtin.py` で確かめた）:
  5〜8 `"¥"#,##0;"¥"\-#,##0` ほか（xljs は標準の表示）、23〜26 `$#,##0_);($#,##0)` ほか、
  37〜40 は日本語版では `#,##0;-#,##0`・`#,##0;[Red]-#,##0`・`#,##0.00;-#,##0.00`・`#,##0.00;[Red]-#,##0.00`（xljs は英語版の `#,##0 ;(#,##0)` で、負の数が括弧になる）、
  41〜44 会計（`_ * #,##0_ ;_ * -#,##0_ ;_ * "-"_ ;_ @_ ` ほか）、59〜62 は `0`・`0.00`・`#,##0`・`#,##0.00`（xljs は先頭に `t` が付く）、63〜81 は 5〜8・9・10・12〜22・45〜47 と同じ。
- **標準（General）**: Excel は小数点も含めて 11 文字に収める（`0.333333333`、`142857.1429`）。12 桁以上の整数と小さな数は指数（`1.23457E+11`、`1.42857E-06`）。指数は `1E+20`。
  xljs は有効数字 11 桁（`0.33333333333`）、整数は 15 桁まで、指数は `1E20`。
- **分数 `# ?/?`・`# ??/??`・`?/?`**: 未対応。
- `0.00E+00` で負の数が `--1.23E+03`。`##0.0E+0`（工学表記）が `4.6E+04`（Excel は `46.1E+3`）。
- 負の数に日付・時刻の表示形式: Excel は `####`、xljs は `-yyyy/m/d1235` のような文字列。
- 1 未満の値に日付の表示形式: Excel は `1900/1/0`、xljs は `1899/12/31`。

### 3.3 数式の文字列（`cell.formula`）

- テーブルの同じ行の参照が `果物[[#This Row],[数量]]` と読める。Excel の表示は `[@数量]`。
- 範囲に入れた配列数式（Ctrl+Shift+Enter）の左上以外のセルは `formula` が null。Excel はどのセルでも同じ数式を返す。
- `'値'!A4` のように不要な引用符を付けて書いた数式はそのまま残る（Excel は `値!A4` にする）。害はない。

### 3.4 書き込み（小さなもの）

- `setColumnWidth("E", 30)` が Excel では 29.38 になる（ファイルの `width` は文字幅に余白を足した値。Excel の「列の幅 30」は `width="30.625"` 前後）。
- 改行を含む文字列を書いても「折り返して全体を表示」が付かず、Excel では 1 行に見える（Excel で Alt+Enter で入力すると付く）。

## 4. テストのデータで直したもの

`testdata/xlsx/calc.xlsx` は Excel で開けなかった（`配列!I4` の `SUM(G1#)` がファイル上で `#` のまま）。また Excel 2010 以降の関数 12 個
（`MAXIFS`・`IFS`・`TEXTJOIN`・`XMATCH`・`LET` など）が `_xlfn.` なしで入っていて、Excel では `#NAME?` になっていた。
xljs と LibreOffice は接頭辞がなくても計算するので気づかなかった。`make_calc.py` の `to_file()` が Excel の保存する形に直す。
