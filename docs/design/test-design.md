# スクリプトの自動テスト（`xljs test`）の設計

AI チャットに書かせたスクリプトを、直すたびに壊していないか確かめる仕組み。記録・再生型（ゴールデンテスト）で、
**AI はテストを書かない・読まない・直せない**ことを原則にする。

- テストの持ち主は xljs と利用者。正解を決めるのは、結果を見て「合っている」と言える利用者だけ。
- AI に渡るのは、失敗したときの短い依頼文（差分）だけ。`docs/ai/` の資料にテストの説明を足さない（コンテキストを使わない）。
- vitest 型（`*.test.js` に `expect`）とアノテーション型（JSDoc から生成）は採らない。どちらも正解を AI が決めることになり、
  失敗したときに期待値のほうを書き換えるのが AI にとっていちばん楽な「修正」になる。スクリプトは「1 ファイル・`ui.form` の
  `onSubmit` に処理」の形なので、関数の export や UI のモックを AI に書かせることにもなる。

## 用語

| 語 | 意味 |
|---|---|
| ケース | 1 つの使い方（入力ファイルと応答の組）。`<スクリプトのフォルダ>/.xljs/tests/<ケース名>/` |
| パターン | ケースの応答を少し変えたもの（境界値など）。`case.json` の `variants` |
| 台本 | 1 回の実行でスクリプトが画面・コンソール・ファイルに出したものの記録。1 行 1 イベントの JSON |
| 承認 | 実行した台本を期待値として保存すること |

## フォルダ

```
集計.js
.xljs/tests/月次集計/
  case.json        入力。人（と、頼まれた AI）が触るのはここだけ
  input/           入力ファイル。再生のときは作業フォルダの input/ になる
  expected/        期待値。xljs が書く。手では書かない
    _base.jsonl    基本の応答の台本
    <パターン名>.jsonl
```

## `case.json`

```json
{
  "script": "集計.js",
  "now": "2026-04-10T09:00:00",
  "user": { "userName": "yamada", "computerName": "PC01" },
  "args": [],
  "answers": {
    "form": [{ "入力フォルダ": "input", "対象月": "2026-04" }],
    "confirm": [true]
  },
  "variants": {
    "月が範囲外": { "form": [{ "対象月": "2026-13" }] },
    "確認でいいえ": { "confirm": [false] }
  }
}
```

- `script`: スクリプトのフォルダからの相対パス。必須。
- `now`: 実行中の現在時刻（ローカルの壁時計時刻。`2026-04-10` だけなら 0 時）。省くと固定しない（今日の日付を使うスクリプトは毎日結果が変わる）。
- `user`: `xljs.userName`・`xljs.computerName` の値。省いたものは `test`・`TEST-PC`（実行する人で結果が変わらないように、実際の名前は使わない）。
- `args`: `xljs.args`。
- `answers`: モック UI の応答（`--ui-answers` と同じ形式。`src/ui/mock.rs`）。種類ごとの列なので、確認が 1 つ増えてもフォームの応答はずれない。
  種類は `confirm` `prompt` `showOpenFilePicker` `showSaveFilePicker` `showDirectoryPicker` `form` `table` `progress` `app` `credentials`。
- `variants`: パターン名 → 基本との差分。種類ごとに、列の i 番目を基本の i 番目に重ねる（オブジェクト同士はキーごと、ほかは置き換え。
  飛ばす位置は `{}`、`null` は「キャンセル」で置き換え、基本より長い分は足す）。`now`・`args` も書ける（置き換え）。
  パターン名に `\ / : * ? " < > |` と先頭の `_` `.` は使えない（ファイル名にするため）。

読み込みは厳密にする。JSON の誤りは行と列、知らないキーは「`ansers` は使えません。`answers` ですか？」のように近い名前を示して止める（黙って無視しない）。
フォームの応答にフォームにない項目名があれば、実行時に問題として報告する（後述）。

## 再生

パターンごとに次のことをする（`src/testing/run.rs`）。

1. 一時フォルダ（作業フォルダ）に、スクリプトのフォルダを写す（`.` で始まるフォルダと exe は除く。200MB を超えたらエラー）。
   その上にケースの `input/` を `input/` として写す。本物のファイルには書かない（`xljs.scriptDir` に置くデータも写しのほう）。
2. 作業フォルダをカレントにし、設定フォルダ（`XLJS_CONFIG_DIR`。フォームの `remember`）も空の一時フォルダにする。
3. 再生用の UI（`src/testing/replay.rs` の `Replay`）でスクリプトを実行する。画面は一切出さない。
4. 実行の前後で作業フォルダのファイルを比べ、増えた・変わった・消えたファイルの中身を台本に足す。

### 止まらないこと

- `alert`・`notify`・エラー表示・`shell.openPath` などは記録してすぐ戻る。
- `confirm`・`prompt`・ピッカーは記録した応答を返す。**応答が尽きたら、その場でスクリプトを止めて問題にする**
  （「記録にない確認が出ました: confirm("上書きしますか？")」）。キャンセル扱いにはしない（黙って終わる・`while (!prompt())` が回り続けるのを避ける）。
  応答に `null` を書いたものは「キャンセル」。
- フォーム・表は応答が尽きたら閉じる（利用者がウィンドウを閉じたのと同じ。`onSubmit` のあるフォームは何度でも実行できるので、これが普通の終わり方）。
- 応答なしで JavaScript が動き続けたら（既定 30 秒。`--timeout`）、尋ねずに止めて問題にする（`engine/watchdog.rs`。テストの実行では確認を出さない）。
- 使われなかった応答は台本に `unused` として残す（問題にはしない）。入力チェックで止まるパターンでは、その先の確認の応答が余るのが普通のため。
  スクリプトが確認を出さなくなったときは、`confirm` が消えて `unused` が増えるので、差分として見つかる。

止める仕組み: `engine::Options::test`（`TestRun`）の `abort` を `Replay` が立て、UI の natives（`src/api/ui.rs`）が呼び出しの直後に見て、
`exit()` と同じキャッチできない例外で止める（終了コード 125＝`ABORT_CODE`）。

### 毎回同じ結果にする

- 現在時刻: `TestRun::now` があると、スクリプトの前に `Date` を差し替える（`new Date()`・`Date.now()`・`Date()` が固定の時刻を返す。
  `Date.prototype` は元のままなので `instanceof` や Excel から読んだ日付はそのまま）。時刻は進まない。
- 実行者: `xljs.userName`・`xljs.computerName` は `TestRun` の値。
- パス: 台本の文字列に出てくる作業フォルダの絶対パスは取り除く（相対パスにする）。エラーのスタック（`at ...` の行）は台本に入れない（行番号はスクリプトを直すたびに変わる）。

### まだ固定していないもの（計画）

`ad.me()`（実行した人のものが返る）、`fetch`（本当に通信する）、`shell.run`（外部のプログラムが待つと制限時間まで止まる）、
PDF 出力（再生では PDF を作らず、呼び出しだけ記録する）、SQLite の共有モード。これらを使うスクリプトは結果が安定しないことがある。

## 台本

1 行 1 イベントの JSON（キーの順は固定）。`type` で種類が決まる。

| type | 内容 |
|---|---|
| `alert` `notify` `error` | 文面 |
| `confirm` `prompt` | 文面と返した答え |
| `openFiles` `saveFile` `directory` | ピッカーと返した答え |
| `form` | 表示したフォーム（タイトル・ボタン）。続けて項目ごとに `field`（名前・ラベル・種類・必須・選択肢・値・表の列と行） |
| `formError` | 入力チェックのエラー（項目・セル・フォーム全体） |
| `submit` | フォームへの応答（変えた値とボタン）。応答が尽きて閉じたときは `close` |
| `table` `row` | `ui.table`・`ctx.table` の表と行。`select` はその応答 |
| `out` `err` | `console.log`・`ctx.log` など標準出力・エラー出力の 1 行 |
| `progress` `progressEnd` | 進捗の開始と終了（件数） |
| `openPath` `showInFolder` `pdf` `window` | 開こうとしたもの・PDF 出力・ウィンドウ（アプリモードはモックと同じログ） |
| `end` | 終了コードとエラーの文面 |
| `file` | 出力ファイル（増えた・変わったもの）。続けて xlsx は `cell`（シート・番地・表示される文字・数式）、テキストは `line`。ほかは大きさと CRC |
| `removed` | 消えたファイル |
| `unused` | 使われなかった応答（種類と数） |
| `problem` | テストとして成り立たないこと（記録にない問い合わせ・フォームにない項目・形の合わない応答・時間切れ）。**承認できず、必ず失敗** |

- xlsx は書式を比べない（見た目の調整のたびに落ちるのを避ける）。セルは表示される文字（日付は書式どおり）と数式。
- テキスト（csv・tsv・txt・json・md・html・xml・js・ts・css・log・ini・yaml）は UTF-8、だめなら Shift_JIS で読む。
- 1 ファイル 20,000 セル・5,000 行まで。超えた分は数と CRC だけ（`more`）。
- データベース（`.db` `.sqlite` `.sqlite3`）は中身が毎回同じにならないので、あることだけ記録する。

比較は台本の行の差分（`dev::notify` の Myers）。表示は台本を読みやすくした文字（`testing::describe`）に `-`（期待）と `+`（今回）を付ける。

## コマンド

```
xljs test [--approve] [--only <ケース>[/<パターン>]] [--timeout <秒>] [--json] <スクリプトかフォルダ>
xljs test --new <ケース名> <スクリプト>      case.json のひな形と input/ を作る
xljs [--ui=...] test --record <ケース名> <スクリプト> [引数...]   ふつうに実行して、応答をケースとして記録する
```

- 結果はパターンごとに 成功 / 失敗（差分を表示）/ 未承認（期待値がない。台本を表示）/ 問題。
- `--approve`: 未承認と失敗の台本を期待値として保存する（問題のあるものは保存しない）。`--only` で絞れる。
- 終了コード: 失敗か問題があれば 1、なければ 0（未承認だけなら 0）。使い方の誤りは 2。
- `--json`: 結果を JSON で標準出力に書く（開発モードが読む）。

## 記録（`--record`）

スクリプトを本物の UI でふつうに実行し（本物のファイルを読み書きする）、利用者の応答を `case.json` に書く（`src/testing/record.rs` の `Recorder`。
`engine::Options::record`）。終わったら `xljs test` で再生して結果を確かめ、`--approve` で承認する（記録した実行そのものは期待値にしない。
再生で同じ結果が出ることを見てから認める）。

- 応答を取る場所: `confirm`・`prompt`・ピッカー・ウィンドウのない UI の表は UI の natives（`src/api/ui.rs`）、フォームは prelude
  （`recordForm`。ウィンドウのフォームは送信のたびに、ウィンドウのない UI は応答のたびに `native.testRecord`）、表のウィンドウは OK を押したとき。
- フォームの応答は「再生で見えている値（既定値。`remember` の値は使わない）から変わった項目」と `$button`・`$cells`（編集したセル）。
  入力チェックで戻された送信も 1 つの応答。パスワードの項目は書かない。
- フォームのウィンドウを利用者が閉じたところには `null` を書く（再生は `onSubmit` のあとももう一度尋ねるので、次のフォームの応答とずれないように）。
- フォームの項目から開いたピッカー・表のウィンドウの［保存］は、再生では尋ねられないので記録から外す（`native.testForget`）。
- **パスの付け替え**: 選ばれたファイル・フォルダは、選ばれた時点（スクリプトが書き換える前）でケースの `input/` に写し、応答には `input/<名前>` を書く。
  写したフォルダの中のパスはその中の相対パスに、保存先（まだないファイル）は作業フォルダ直下のファイル名にする。`xljs.args` のうち実在するパスも同じ。
  `input/` は合わせて 200MB まで（超えた分は写さず、終わりに知らせる）。
- 再生の側の合わせ: テストの実行（`native.testMode`）では、ウィンドウのない UI のフォーム（`formPrompt`）がフォームのウィンドウと同じ動きをする
  （`onSubmit` のあとも開いたまま＝もう一度尋ねる、`onSubmit` のエラーは表示して続ける）。
- アプリモードのウィンドウの操作、`ui.chart` は記録しない（段階 5）。

## 境界値のパターンの追加（`--suggest`）

`xljs test --suggest <ケース> <スクリプト>`（`testing::suggest`）は、ケースの基本の応答で 1 回実行し、最初のフォームの項目の定義
（台本の `field`。`required`・`min`・`max`・`maxLength`・選択肢は prelude が `uiForm` に渡す）から、最初のフォームの応答を 1 項目だけ変えたパターンを作る。

| 項目 | 作るパターン |
|---|---|
| 必須（チェックボックス・表以外） | 空 |
| 数値で `min` / `max` あり | 下限・下限 − 1・上限・上限 + 1 |
| 数値で制限なし | 0・−1 |
| `maxLength` あり | ちょうどの長さ・1 文字多い |
| `select`・`radio` | ほかの選択肢（8 個まで） |
| チェックボックス | 逆の値 |

- 基本の応答と同じ値になるもの、同じ名前のパターンがあるものは作らない。**追加だけ**で、すでにあるパターンと応答は変えない（`case.json` は整形し直す）。
- 追加したパターンは未承認。結果を見て承認するか、要らなければ消す（`testing::remove`。開発モードでは［削除］）。
- 日付・`pattern`・項目をまたぐ条件・入力ファイルの中身の境界値は作らない（人が `variants` に足す）。

## 開発モード（「テスト」タブ）

`src/dev/mod.rs` のセッションが、別プロセスの `xljs test --json`（`runner::Run`。スクリプトの実行とは別枠の `Session::testing`）でケースを流し、
結果をページ（`dev.js` の tests）に渡す。ケースの検査・再生・比較はすべて `xljs test` の側で、セッションは起動と結果の受け渡しだけをする。

| ページ → Rust（`op`） | 内容 |
|---|---|
| `tests` | スクリプト（入口）のケースをすべて実行する。ケースがなければ実行せず `tests`（`none`）を返す |
| `testApprove` | `name`（`ケース/パターン`、基本は `ケース/`、空ですべて）を `--approve` で実行し、終わったら全体をもう一度実行する |
| `testRecord` | `xljs test --record <name>` をふつうの実行として起動する（`RunKind::Record`。出力は「実行結果」）。`name` が空なら空いている「ケース N」。終わったら全体を実行する |
| `testPrompt` | `name` の結果について AI への依頼文をコピーさせる（`report::test_prompt`） |
| `testSuggest` | ケース（`name`）に境界値のパターンを足し（`xljs test --suggest`）、全体を実行する |
| `testRemove` | パターン（`ケース/パターン`）かケース（`ケース/`。入力ファイルごと）を、確認してから削除する |

| Rust → ページ（`type`） | 内容 |
|---|---|
| `testsStarted` | 実行を始めた（`runs`: 実行の数） |
| `tests` | 結果: `pass` `fail` `new` `problem` と `outcomes`（`name` `status` `lines`。台本のイベントは渡さない）。`none`＝ケースなし、`error`＝実行できなかった理由（`case.json` の誤りなど）、`stopped` |

- 自動で実行するのは、スクリプトを開いたとき（ページが `tests` を送る）、置き換え（`apply`）のあと、記録のあと。
- 自動の実行は、失敗か問題があるときだけ「テスト」タブを前に出す（タブのバッジとステータスには常に出す）。
- 失敗は［これが正しい］（承認）か［AI に直してもらう］。未承認は［これが正しい］だけ、問題は［AI に直してもらう］だけ。
- **依頼文には差分（表示用の行）だけを載せる**。`case.json`・応答・期待値のファイルの場所や書き方は載せない（AI にテストを触らせない）。
  120 行を超える分は省く。最後は実行のエラーと同じ「修正した完全なファイルを出力」。

## 実装の段階

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | ケースの形式と検査、再生、台本、比較、承認、`xljs test`。時刻・実行者の固定 | 実装済み |
| 2 | 記録: 本物の UI で実行しながら応答を `case.json` に、選ばれたファイルを `input/` に写してパスを付け替える（`xljs test --record`）。ネイティブのフォームは prelude の `formWindow` で送信の値を記録する | 実装済み（Windows 実機のウィンドウでの確認はまだ。偽のページのテストのみ） |
| 3 | 開発モード: ［テストとして記録］、置き換えのたびに自動で実行して「テスト 3/3」、失敗の差分と［これが正しい］（承認）・［AI に直してもらう］（`src/dev/report.rs` に依頼文） | 実装済み（ページは偽のメッセージでブラウザ表示を確認。Windows 実機の WebView2 での確認はまだ） |
| 3b | 失敗したとき、記録した `form` と今の `form` を `form.html?preview` で並べて見せる。ケースの削除・名前の変更、パターンの編集の画面 | 未着手 |
| 4 | 境界値の候補: フォームの項目の定義（`required` `min` `max` `maxLength`・選択肢）から機械的にパターンを作る（`xljs test --suggest`、開発モードの［境界値のパターンを追加］）。パターン・ケースの削除 | 実装済み |
| 4b | AI に増やさせる: 項目の定義だけを渡し、`variants` に足す分だけを受け取って取り込む（追加のみ）。`pattern`・日付の境界値 | 未着手 |
| 5 | `ad.me()` の記録、`fetch` の記録と再生、セルの上書き（`"cells": { "input/売上.xlsx": { "明細!E2": "abc" } }`）、アプリモードの操作の記録 | 未着手 |

## テスト

- `src/testing/tests.rs`: 形式の検査（誤りの場所と候補）、パターンの重ね方、再生（フォーム・確認・出力ファイル・時刻）、
  記録にない問い合わせ・使われなかった応答・無限ループ、承認と比較（ケースはテストの中で一時フォルダに作る）。
  記録は、モック UI を利用者に見立てたもの（ウィンドウのない UI）と、ページのメッセージを送る偽のウィンドウ（フォーム・表のウィンドウ）で、記録 → 再生まで通す。
- `src/cli/test.rs`: `xljs test` の引数。
- `src/dev/tests.rs`（`test_cases_in_the_session`）: ケースなし・ケースの誤り・結果の受け渡し・依頼文・記録の名前の検査。
